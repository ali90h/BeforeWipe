# Security and privacy

Use plans and selections you have reviewed. Default assessment intentionally avoids work-file contents, conversations, Git config, object contents, shell commands, and network access. It reads selected Git structural metadata and directory/file metadata. Optional `verify` reads only explicit selections after `--allow-content-read`; that flag asserts both copies contain no secrets. Sensitive-name exclusions are a guardrail, not a scanner for embedded secrets.

Hardlinked plans and Git structural files are refused before byte reads. File identity is checked before reading and after comparison; declared recovery roots are checked for replacement. These checks detect the tested substitution cases, not every possible concurrent change. Keep scopes stable. Do not assess an untrusted repository that may have placed sensitive bytes inside apparently ordinary Git metadata; filenames and valid-looking structure cannot establish content provenance. The tool is not a security sandbox.

Optional `--allow-git-object-read` separately authorizes local loose HEAD commit/tree reads for every declared project in that invocation. Review their object contents as non-sensitive first: reads include commit messages and filenames. Malformed or disguised objects can hold arbitrary bytes, including secrets, and must be read before type/hash validation. This option must not be used on unreviewed or secret-bearing repositories. It does not traverse blob entries, packfiles, alternates, config, or external stores and never executes Git. Missing loose objects remain unknown. Ordinary selected-content consent does not grant this access, and object-read consent does not grant selected-file access.

The object reader uses existing descriptor-relative no-follow, regular-file, single-link, size, identity, and replacement checks. It bounds compressed/expanded bytes, entry counts, and depth, validates zlib framing, type, length, and SHA-1 identity, and emits only aggregate counts and fixed reason codes. These checks do not authenticate repository provenance or prove blob availability. A hostile object reached through a commit/tree reference could still cause arbitrary in-scope bytes to be read with expanded authorization. Keep default mode when that risk cannot be reviewed.

Do not submit real session transcripts, plans with personal paths, credentials, repositories with confidential work, or unreviewed reports to an issue tracker. Reproduce bugs with synthetic fixtures. Reports omit paths and content but still reveal item IDs and aggregate work metadata.

Keep assessment data stable during checks. No complete-machine safety conclusion is available. A matching local file copy is not evidence of independent backup durability. Use your backup tool and independently test a restore before considering a wipe.

Default mode leaves staged-only work unknown. The optional comparison can detect index/HEAD differences; packed objects and unsupported/incomplete cases remain explicit gaps. Matching working files do not preserve versions stored only in Git's index-referenced objects. Review staging independently and verify a repository restore including index and objects. See the [original review and pilot assessment](docs/ENGINEERING_SECURITY_REVIEW.md) and [staged-work implementation note](docs/STAGED_WORK_DETECTION.md) for tested boundaries and remaining barriers. The [independent object-reader review](docs/GIT_OBJECT_SECURITY_REVIEW.md) records reproduced defects, fixes, and conditional pilot requirements. It does not establish an unconditional secret-avoidance or filesystem-sandbox guarantee.

If reporting a vulnerability, describe the behavior and a minimal synthetic reproduction. Never include a working credential, real transcript, or personal machine scan. Use the repository's Security → Report a vulnerability option when available. There is no designated private disclosure email. If the private option is unavailable, open only a generic request for a private contact, without exploit details or sensitive data, and wait for a private channel before sharing details.
